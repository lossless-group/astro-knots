# Every Astro Knots Doc Now Says Where It Stands

## Why Care?

We're building a dashboard that manages work across every `context-v/` in the tree: what's ready to pick up, what's in flight, what's a standing rule. It groups by `status:`, and in `astro-knots/` a third of the docs used a word it couldn't place. `Published` alone covered 23 docs that were really two different things: rules agents should follow, and explanations they should consult.

## What's New?

- **Reminders are `Active`**: rules in force (12 docs).
- **Architecture blueprints, sitemap docs, and the generated wikilink audit are `Reference`**: accurate accounts of how something is built (11 docs). Two blueprints that state a standard are `Active`.
- **Three docs are `Partially-Shipped`**, each on evidence in the tree: the wikilink resolver (208 of 354 links resolved, per its own status line), the reading-position table of contents (shipped in fullstack-vc on 2026-08-17), and the brand-theme setup prompt (its body lists what's done and what's left).
- **Dynamic OpenGraph images is `Deferred`**, with its own reason recorded as the `deferral_note`: Vercel deployment pending.
- **Ideas, proposals, an unproven loop, and an open exploration are `Draft`** (7 docs). Nothing in the tree shows the work started.

## Under the Hood

- The vocabulary comes from the expanded `status-discipline.md` in the context-vigilance skill, which groups values by kind of doc: planned work, issues, decisions, standing docs, and any doc.
- These are judgment calls made by reading each doc and checking the sites for shipped components. A status is a claim, so each one maps to something in the repo.
- No dates moved except one: the reading-position spec's `date_first_published` went from `null` to 2026-08-17, the day fullstack-vc shipped it.
- The `Partially-Shipped` docs don't yet have a `## Remaining work` section; their existing status notes carry that for now.
