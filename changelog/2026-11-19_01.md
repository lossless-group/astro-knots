# AI Camp Joins the Tree, Skill Packs Get a Home, and Two New Plans for Running and Publishing

## Why Care?

A new client site now lives alongside the rest, and its redesign is being run
in a way other live clients can copy: keep the current site steady at `/`, and
show the options under `/directions`. Skill repos we fork from other people now
have a clear place to live. Two new documents plan how agents can keep working
when the laptop is closed, and how published memos and decks could be edited
live without a site rebuild.

## What's New?

### ai-camp-site joins as a submodule

`sites/ai-camp-site` points at `ai-camp-org/ai-camp-site`, tracking
`development`.

### Design variants for a live client

The `generate-site-design-variants` skill gains a **live-client variant**. The
current site is replicated and holds `/`. Each option lives under
`/directions/<slug>` as a full design system. Options render through a bare
shell layout that imports no system CSS, and a post-build check fails the build
if any system styles or another option's styles leak in. The reference
implementation is in `sites/ai-camp-site`.

### `context-v/skill-packs/` (experimental)

A new folder for third-party repos that bundle many skills, usually forks into
the `lossless-group` org. The first is `seo-skills`, our fork of
`Illyism/seo-skills`: 30 SEO skills covering technical audits, SERP workflows,
backlinks and GEO. `context-v/README.md` explains how a skill pack differs from
`agent-skills/`.

### Blueprint: Run an Astro Knots Site on boxes.dev

How to give each coding agent its own cloud computer with the site already
running, with `cathode-site` as the pilot. It is still a draft, and its claims
need checking against a first real run.

### Spec: Live Content on Cloudflare Artifacts, Wrapped in an MCP

Each deal's published memos and decks would live in their own Artifacts repo.
An MCP would let people and agents iterate on them and publish, and the site
would render whatever is on `main`. Draft.
