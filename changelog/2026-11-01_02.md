# Astro Knots' Docs Get Their Missing Dates, Authors, and Lists

## Why Care?

[[2026-11-01_01]] made `astro-knots/context-v/` an Open Knowledge Format bundle. This pass brings the same docs up to the Context Vigilance Kit's baseline frontmatter, so the splash, the corpus roll-up, and any agent reading them get the same fields in the same shape on every doc.

## What's New?

- **17 docs gain a `date_modified`** and one a `date_created`. The values are facts, not today's date: each file's last commit before the sweep, or its own first-draft date.
- **Two docs gain `authors`**, from their only human committer.
- **47 single-string `augmented_with` values become one-item lists**, the string kept word for word. The convention is a list, and the splash already reads both.
- **Two tags were re-cased to Title-Case:** `Component-Based-Architecture` and `Style-Prefix`.
- **The `mpstaton-site` tag comes off three docs.** A repo name isn't a topic, and all three already name the site in their body.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]].
- Every edit was made by hand. No body line changed, no existing key was deleted, and no `publish`, `status`, or lede value moved.
- Every doc already had a `site_uuid` and `hex_code`, so no IDs were minted.
- Most of the new `date_modified` values point at 2026-08-18, the date of a bulk frontmatter commit, not a content edit. That is still the last time each file changed, which is what the field records.
- Left as found, for a later reading pass: `"[]"` date placeholders, a few `date_created` values that disagree with their first-draft date, non-standard `status` words, and three reminders that share one copy-pasted tag set.
