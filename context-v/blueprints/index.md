# Blueprints

* [Build a Fundraise Deck Workspace](Build-a-Fundraise-Deck-Workspace.md) - Step-by-step playbook for standing up a private, gated, two-surface fundraise deck workspace, as proven on `sites/calmstorm-decks`.
* [Build a Promotion Surface for Investment Opportunities](Build-a-Promotion-Surface-for-Investment-Opportunities.md) - A hard-gated `/promote` hub per opportunity, surfacing deck and memo behind real auth, built for 3–5 minute variant iteration cycles.
* [Build an Upgrade Ladder Cart from Superset Tiers](Build-an-Upgrade-Ladder-Cart-from-Superset-Tiers.md) - Make every tier a strict superset of the one below and the cart can show you the delta instead of swapping in a whole new cart.
* [Citation System Architecture](Citation-System-Architecture.md) - A citation and reference management system for Astro sites using hex codes as stable identifiers that convert to sequential integers at render time.
* [Codeblock Syntax Highlighting with Shiki](Codeblock-Syntax-Highlighting-with-Shiki.md) - Blueprint for implementing syntax-highlighted code blocks across astro-knots sites using Shiki with the tokyo-night theme and reusable wrapper components.
* [Confidential Content Access Control Blueprint](Confidential-Content-Access-Control-Blueprint.md) - A tiered pattern for protecting privileged or confidential content across astro-knots sites, from simple passcodes to full OAuth integration.
* [Continuous Integration for Astro Knots Sites](Continuous-Integration-for-Astro-Knots-Sites.md) - Every Astro Knots site has a deploy workflow and none has a test. That is defensible right up until a site imports package source, ships a broken link, or renders raw `[[wikilinks]]` to production — none of which a successful build notices.
* [Generate a Pseudomonorepo Rollup of Changelog and Context](Generate-a-Pseudomonorepo-Rollup-of-Changelog-and-Context.md) - Deliberate sync: a human runs `pnpm rollup:sync`, each child's changelog and context-v lands in `src/rollup/`, and the build stays file IO.
* [GitHub Secure Content Pattern](GitHub-Secure-Content-Pattern.md) - A pattern enabling Astro sites to fetch confidential content from a private GitHub repository at runtime, keeping sensitive documents out of static assets.
* [Guarantee Text Wrapping and No Horizontal Bleed at Any Width](Guarantee-Text-Wrapping-and-No-Horizontal-Bleed-at-Any-Width.md) - One Tailwind class caused it: `mx-auto` on a flex item disables stretch, so `<main>` sized to its content instead of its parent.
* [Jumbotron Popdown Patterns](Jumbotron-Popdown-Patterns.md) - Design and implementation patterns for consistent jumbotron popdown menus in the Lossless UI.
* [Maintain Base Engagement Analytics](Maintain-Base-Engagement-Analytics.md) - Page views say someone arrived. Time on page, scroll depth and downloads say whether they read it. One definition of each, for every site.
* [Maintain a Branch-Aware LFM Dev Mode](Maintain-Branch-Aware-LFM-Dev-Mode.md) - A per-site swap script that lets a development branch consume @lossless-group/lfm from the local workspace while every deployable branch consumes the canonical JSR build — so production deploys can never accidentally ship a workspace link.
* [Maintain Confidential Access with Persistent Sessions and Auth Telemetry](Maintain-Confidential-Access-with-Persistent-Sessions-and-Auth-Telemetry.md) - Signed pre-authed links for named stakeholders, passcodes for everyone else, and telemetry so every silent auth failure leaves a row.
* [Maintain Design System and Brand Kit Motions](Maintain-Design-System-and-Brandkit-Motions.md) - Every Astro-Knots site ships `/brand-kit` for stakeholders and `/design-system` for developers — this is the scope split and the upkeep.
* [Maintain Embeddable Slides](Maintain-Embeddable-Slides.md) - Markdown slide decks already embed via a `:::slides` directive; Astro-component decks do not — the embed route only reads `.md` files.
* [Maintain an Extended Markdown Render Pipeline for Astro-Knots](Maintain-Extended-Markdown-Render-Pipeline.md) - A simplified, Astro-Knots-specific blueprint for rendering extended markdown across sites, starting with Hypernova and Dark-Matter as first adopters.
* [Maintain Privacy Gates in Three Modes](Maintain-Privacy-Gates-in-Three-Modes.md) - One gate, three doors: a shared passcode, a verified email on the firm's list, or a link minted for one person. Each opens only what it names.
* [Maintain Themes and Modes Across CSS and Tailwind](Maintain-Themes-Mode-Across-CSS-Tailwind.md) - Implementation blueprint for dual-axis theme and mode control using Tailwind CSS v4 custom properties, with runtime utilities and Vitest verification.
* [Maintain an Elegant Open Graph System](Maintain-an-Elegant-Open-Graph-System.md) - A scalable, consistent architecture for Open Graph metadata optimized for the messaging-first share economy.
* [Maintain an Interactive Polling System](Maintain-an-Interactive-Polling-System--v2.md) - Embeddable theme-aware polls on Astro SSG: the Session/Poll model, Astro DB on Turso, DB→markdown archive, Svelte + GSAP UI contracts.
* [Maintain an Interactive Polling System](Maintain-an-Interactive-Polling-System.md) - Embeddable theme-aware polls on Astro SSG: data model, flat-file→database storage progression, vote integrity, Svelte + GSAP contracts.
* [Managing Complex Markdown Content at Build Time](Managing-Complex-Markdown-Content-at-Build-Time.md) - Patterns and tradeoffs for managing markdown content that lives outside an Astro project but must be available at build time, with strategies for Vercel deployment.
* [Slides System for Astro and Markdown](Slides-System-for-Astro-and-Markdown.md) - A comprehensive specification for building presentation slide systems in Astro-Knots sites with RevealJS, Three.js, and full theme/mode integration.
* [A Standard Table of Contents for Every Markdown Collection](Standard-Table-of-Contents-for-Every-Markdown-Collection.md) - One reading-position ToC everywhere, built on LFM's heading outline — the only source that tells a heading from a `#` inside a code fence.
* [Styles Architecture Blueprint](Styles-Architecture-Blueprint.md) - Architecture blueprint for Dark Matter's CSS and Tailwind v4 theming system, defining named brand colors, derived scales, semantic tokens, and three display modes.
