## Why Care?

v0.1.0 shipped the two-perspective how-to engine — but its pages rendered raw markdown with no prose styling, so every section heading sat at body size. A how-to you can't scan isn't much of a how-to. This patch makes the content readable.

## What's New Since v0.1.0

- **Shared `docs-prose.css`** — one global stylesheet articulating the LFM / `AstroMarkdown` output (`h1`–`h4`, lists, blockquotes, inline code, tables, rules, images), applied via a `.docs-prose` wrapper on the guide, use-case, and tool body. Mirrors the site's `MarkdownReader` treatment, so the docs read like the rest of the long-form content and inherit all three theme modes.
- **Redundant body title removed** — the markdown body's `# Title` is gone; the page header already renders it, and bodies now start at `##` (the `MarkdownReader` convention).

## Why It Was Bare

The project's own house rule names it: **Tailwind's preflight resets headings to base size**, so markdown rendered without scoped prose styles inherits that. The site solves it twice already (the session page; `MarkdownReader`), but the brand-new docs routes had neither. We factored the treatment into one global stylesheet instead of copying a third scoped block.

## Operational Hand-Off

- **Tag** `v0.1.1` — a **patch** on v0.1.0 (styling/readability only; no behavior or schema change).
- **`package.json`** bumped `0.1.0` → `0.1.1` to match.
- No new type debt; `astro check` held at its pre-existing baseline.

## What's Next

Unchanged from v0.1.0: the docs chrome (left-nav, right-hand TOC, prev/next pagination) is specced and waiting, and the engine wants more guides to pressure-test the two-perspective structure.
