# Changelog - 2025-12-14 (#2)

## Hypernova Site: Slides System Architecture Refactor — Layout Composition, Adaptive Typography, and Control Bar UX

### Overview

This sprint addressed critical architectural and UX issues in the slides system:

1. **Layout Composition Pattern** — OneSlideDeck now uses BoilerPlateHTML as its foundation, ensuring proper mode-switching inheritance.
2. **Adaptive Typography** — Font sizes now scale responsively using CSS `clamp()` functions.
3. **Control Bar UX** — Centered control bar with proper content offset to prevent overlap.
4. **Light Mode Fixes** — Solid button backgrounds instead of transparent for better visibility.

**Key Achievement:** A clean component composition model where slides properly inherit mode-switching from the single source of truth (BoilerPlateHTML).

---

## Architecture Changes

### Before: Duplicated Boilerplate
```
BaseThemeLayout.astro (has header/footer)
    └── Used by normal pages

OneSlideDeck.astro (created its own HTML document!)
    └── Standalone, duplicated mode-switching logic
```

**Problem:** OneSlideDeck duplicated BoilerPlateHTML's functionality, creating maintenance burden and bypassing the single source of truth for mode switching.

### After: Proper Composition
```
BoilerPlateHTML.astro (base HTML boilerplate + mode switching)
    ├── bodyClass prop (NEW)
    ├── <slot name="head" /> (NEW)
    │
    └── OneSlideDeck.astro (RevealJS wrapper)
            ├── passes bodyClass="slide-deck-active"
            ├── uses head slot for RevealJS CSS
            └── SlidesControlButtons.astro
```

**Solution:** OneSlideDeck now composes from BoilerPlateHTML, inheriting all mode-switching logic while adding slide-specific styling via `bodyClass` and `head` slot.

## Changes by Area

### 1. BoilerPlateHTML Enhancement

**Modified: `src/layouts/BoilerPlateHTML.astro`**

Added two new capabilities for composability:

```astro
<!-- New Props -->
export interface Props {
  title: string;
  description: string;
  themeClass: string;
  bodyClass?: string;     // NEW: Allow layouts to add body classes
  // ...
}

<!-- New Named Slot -->
<head>
  <slot name="head" />  <!-- NEW: Allow layouts to inject head content -->
</head>

<body class={bodyClass}>
```

### 2. OneSlideDeck Refactor

**Modified: `src/layouts/OneSlideDeck.astro`**

Complete rewrite to use BoilerPlateHTML:

```astro
<!-- Before: Created its own HTML document -->
<html lang="en" class="theme-hypernova dark">
  <head>...</head>
  <body>
    <div class="reveal">...</div>
  </body>
</html>

<!-- After: Composes from BoilerPlateHTML -->
<BoilerPlateHTML
  title={title}
  description={description}
  themeClass="theme-hypernova"
  bodyClass="slide-deck-active"
>
  <link slot="head" rel="stylesheet" href="reveal.min.css" />
  <SlidesControlButtons />
  <div class="reveal-container">
    <div class="reveal">
      <div class="slides">
        <slot />
      </div>
    </div>
  </div>
</BoilerPlateHTML>
```

### 4. Adaptive Typography

**New CSS using `clamp()` for responsive font sizes:**

```css
.reveal h1 {
  font-size: clamp(1.75rem, 5vw + 1rem, 4rem);
  line-height: 1.1;
}

.reveal h2 {
  font-size: clamp(1.5rem, 3.5vw + 0.75rem, 3rem);
  line-height: 1.2;
}

.reveal h3 {
  font-size: clamp(1.25rem, 2.5vw + 0.5rem, 2.25rem);
  line-height: 1.3;
}

.reveal p {
  font-size: clamp(1rem, 1.5vw + 0.5rem, 1.5rem);
  line-height: 1.6;
}

.reveal li {
  font-size: clamp(0.95rem, 1.4vw + 0.45rem, 1.4rem);
  line-height: 1.5;
}
```

### 5. Control Bar Positioning

**Modified: `src/components/slides/SlidesControlButtons.astro`**

Centered control bar with content offset:

```css
/* Control bar positioning */
.control-buttons {
  position: fixed;
  top: 1rem;
  left: 50%;
  transform: translateX(-50%);
  z-index: 9999;

/* Content offset to clear control bar */

```

### 6. Solid Button Backgrounds

**Fixed: Light mode button visibility**

```css
/* Before: Transparent backgrounds washed out in light mode */
.control-button {
  background: rgba(var(--color-primary-800), 0.3);
}

/* After: Solid backgrounds for visibility */
.control-button {
  background: rgb(var(--color-primary-800));
  color: rgb(var(--color-primary-50));
  border: 1px solid rgba(var(--color-primary-600), 0.5);
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.2);
}

/* Light mode overrides */
html[data-mode="light"]:not(.dark) .control-button {
  background: white;
  color: rgb(var(--color-primary-900));
  border: 1px solid rgb(var(--color-primary-200));
}
```

## Key Lessons

1. **Component Composition > Duplication** — When a layout needs specialized behavior, extend the base rather than duplicating it.

2. **Named Slots for Composability** — Using `<slot name="head" />` allows child layouts to inject content into specific areas without breaking encapsulation.

3. **Solid vs Transparent** — For UI elements that need to work in both light and dark modes, solid backgrounds with mode-specific overrides are more reliable than transparent backgrounds.

4. **Content Offset Pattern** — Fixed position elements (like control bars) should use a container offset pattern (`top: 4rem; height: calc(100% - 4rem)`) rather than padding on content.

5. **CSS clamp() for Typography** — The `clamp(min, preferred, max)` function provides responsive typography without media queries.
