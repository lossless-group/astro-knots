## What changed and why

Routine maintenance pass following the Astro 6→7 upgrade completed earlier this session. Ran `pnpm outdated` against the site and found only two packages behind:

- `@astrojs/sitemap`: `3.7.2` → `3.7.3` (patch)
- `svelte`: `5.55.8` → `5.56.4` (minor)

Both bumped via `pnpm update`. Everything else already-installed (`astro` `7.0.6`, `@astrojs/vercel` `11.0.2`, `@astrojs/svelte` `9.0.1`, `tailwindcss` `4.3.2`, `@tailwindcss/vite` `4.3.2`) was already at latest — no further updates available.

## Also included

- Added `@astrojs/check` and `typescript` as devDependencies (matching the versions used in `twf_site`/`hypernova-site`: `@astrojs/check@^0.9.9`, `typescript@^6.0.3`). The site previously had no way to run `astro check` at all — this is the first time typechecking has been wired in since the site's scaffold.
- Ran `pnpm exec astro check` with the newly-added tooling. Surfaced one pre-existing type error in `src/lib/services.ts:160` (a `number | null | undefined` vs `number | undefined` mismatch on `rateUnits[].multiDayBlock`) plus a batch of `z is deprecated` hints in `src/content.config.ts` from Zod's re-export in newer Astro content collection types. Neither is related to this dependency pass — left as-is per the maintenance-pass scope; flagging here for a future fix pass on `src/lib/services.ts`.
- `pnpm build` verified clean before and after the bump, and again after the version-field bump.

## Build verification

- `pnpm build` — clean, all routes prerendered, Vercel adapter output produced successfully.
- `pnpm exec astro check` — runs (previously could not run at all); 1 pre-existing unrelated type error, 127 hints (mostly the Zod deprecation notices), 0 new warnings introduced by this pass.
